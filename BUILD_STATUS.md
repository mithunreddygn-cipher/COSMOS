# COSMOS Build Status

Last updated: 2026-11-15

## Completed in this implementation pass

- Preserved the existing modular packages for `ingest`, `quality`, `gate`, `science`, `detect`, `investigate`, and `report`.
- Connected recognized 2-D FITS image HDUs to source extraction, flags masking, background estimation, aperture photometry, variance-aware uncertainties, WCS coordinates, source matching, and the shared scientific pipeline.
- Exposed Photutils segmentation-moment morphology (ellipticity, elongation, eccentricity, image-plane orientation, and semiaxis scales) as per-source measurements. These are explicitly uncalibrated observed shapes, not PSF-deconvolved classifications.
- Added exact weighted aperture-coverage reporting. Flagged or invalid overlap withholds the full-aperture flux; the partial sum is diagnostic only and no area correction is fabricated. Limited/incomplete FITS measurements are blocked from temporal detection.
- Made automatically generated instrumental-artifact hypotheses UNTESTABLE absent a hypothesis-specific prediction and demonstrated detectability. A present EPSF is reported as availability, not analysis.
- Split temporal wavelength coverage from instrument-response evidence. Temporal detection requires a RUNNABLE Gate and explicit validated response-equivalence evidence or a confirmed applied correction to a common reference; legacy compatibility booleans and matching detector labels do not authorize it.
- Connected explicitly measured CSV/ECSV/VOTable rows to the same temporal, spatial, and spectral detector interface when canonical columns are present. Incomplete records are omitted from that measurement path and reported.
- Preserved recognized tabular measurement rows in the generated report, including source/observation IDs, units, source file hash, and row number, in addition to the FITS-derived measurements.
- Kept per-source detector series separate. Spectral tests are also separated by source and observation so measurements from different epochs are not silently treated as a spectrum.
- Added dedicated WCS-WAVE table parsing that retains raw X/Y/VALUES arrays, dimensions, and dtypes while reporting parse, structural, and semantic statuses plus detector, coordinate, unit, and schema metadata.
- Added a separate documented mapping-specification layer. The current supported mapping is an explicit IMAGE_PIXEL identity mapping with declared channel meanings/units and bilinear interpolation; unsupported coordinate transformations are rejected and extrapolation requires explicit documented authorization.
- Source-level wavelength/bandwidth values are emitted only when the calibration map is explicit and uniform across the complete valid aperture. No centroid-only wavelength lookup is used. WCS-WAVE availability never establishes response compatibility.
- FITS-derived spectral points require a valid source measurement, positive uncertainty, explicit source/observation association, and a validated source wavelength. The spectral detector rejects unassociated or mixed-source/mixed-observation points.
- Added a reusable sky-coordinate source-association module. It sorts by parsed time, constrains matches by detector/band/frame and configurable angular tolerance, uses positional uncertainty in confidence, and leaves ambiguous, duplicate, untimed, or invalid-WCS measurements unmerged.
- Added a separately gated Lomb-Scargle periodicity screen for compatible single-source light curves. It requires at least 10 distinct epochs, explicit matching units/bandpass, and valid positive uncertainties; it reports the search range, peak power, Baluev false-alarm estimate, and supporting observations without making a discovery claim. Pipeline callers can configure minimum/maximum periods and the false-alarm threshold via `periodicity_options`; per-source processing is bounded to 10,000 epochs and 100,000 frequency samples.
- Added source-level temporal classifications and angular-motion investigation. Flux comparisons require a RUNNABLE Compatibility Gate, valid uncertainties, consistent units/bandpass, and at least three epochs. Transient candidates require explicit sensitivity-backed compatible detection states; missing observations are not treated as zeros.
- Integrated a structured `multi_epoch_investigation` result and report section containing the observation timeline, source counts, tracks, associations, source classifications, candidates, unresolved matches, compatibility failures, duplicate inputs, and limitations.
- FITS processing preserves instrument, detector, calibration, processing-version, observation, product, and file-hash provenance where available. Added an ordered pipeline timeline from FITS ingestion through quality, association, compatibility, temporal/spatial investigation, hypothesis evaluation, and reporting.
- Added measurement-backed quality findings, observation provenance, computed candidate evidence cards, runtime-version provenance, and JSON/CSV/HTML report exports.
- Extended JSON/HTML report structure with per-product measurement methods and limitations, observation-level calibration evidence, and a concise detector/source algorithm trace.
- Kept the CSV export explicitly scoped to candidate/finding rows; JSON and HTML remain the full investigation reports.
- Built COSMOS Mission Control with five research sections: Mission Control, Explore Observations, Source Explorer, Investigation Results, and Scientific Reports. The dashboard metrics, observation timeline, compatibility/quality panel, event log, and result views are populated from pipeline output.

## Remaining modules and limitations

- **Real SPHEREx product validation:** limited to the inspected saved QR3 Level-2 D5 science product and one separately downloaded official D5 Spectral WCS calibration release. The science product has seven HDUs and a 29×29 image; its WCS-WAVE table parses structurally (one row; X/Y length 11; VALUES shape 11×11×2), and raw values/dtypes are preserved. The official calibration product has separate 2040×2040 CWAVE and CBAND maps and 121 WCS-WAVE controls; detector/coordinate metadata and declared micron units validate, and its control values match the saved science table and the maps at those points. Its supported cutout-to-calibration translation is therefore usable for calibration-map sampling, but the science header has no authoritative calibration-version association. WCS-WAVE is used only as a consistency check; it is not treated as full-response evidence. The laboratory CSV is representative-only. Full instrument response remains UNVALIDATED, no source wavelength/bandwidth is claimed unless its complete valid aperture is uniform, and quantitative spectral comparison remains gated. This one-product result does not validate general SPHEREx compatibility, astrometric accuracy, flag semantics, variance calibration, or ePSF performance.
- **IRSA network verification:** one successful saved SIA2 query reports 132 rows and 66 distinct observation IDs/start times; one product was downloaded and inspected. Pagination behavior, repeated requests, and broad product-download reliability remain unverified. No network failure is labeled as an empty sky.
- **Barnard's Star:** no source-level identity has been confirmed. The downloaded product is a field exposure, and no detected source has been matched to Barnard's Star with independent astrometry.
- **PSF handling:** PSF/ePSF availability is recorded. PSF fitting, aperture correction, PSF matching, and spatially varying PSF quality checks are not implemented.
- **Morphology:** reported moments describe the detected segmentation in pixel coordinates. They are not deconvolved or compared with a calibrated PSF, and do not establish whether a source is intrinsically extended.
- **Image registration/arithmetic:** the UI can execute an operation on selected uploaded/cached products only if exact WCS signatures and dimensions, pixel scales, PSF data, masks, backgrounds, units/calibration, and variances all pass. General WCS reprojection, PSF convolution/matching, and spatial background matching are not implemented, so many real product pairs will correctly be blocked.
- **Spectral analysis:** the detector requires at least five distinct wavelength/flux/uncertainty points with explicit source and observation identity plus explicit response compatibility. Structurally parsed WCS-WAVE data are not interpreted without a documented mapping spec. Source calibration values are withheld unless uniform across the complete valid aperture. Calibrated multi-product spectral assembly and response-curve comparison remain unimplemented; COSMOS does not independently inspect or validate response curves. The Streamlit UI does not accept mapping specifications.
- **Spectral interpretation:** local-continuum outliers are screening measurements only. Emission/absorption line identification, physical continuum fitting, thermal/blackbody models, and redshift estimation are not implemented.
- **Tabular interoperability:** CSV/ECSV/VOTable data can enter analysis through canonical fields, but table-column unit metadata is retained rather than automatically normalized. Supply values in the canonical units (for example `wavelength_um`, `ra_deg`, and `dec_deg`) and explicit flux units. FITS binary tables are not yet routed to the measurement analyzers; arbitrary FITS images are never treated as calibrated measurements by suffix alone.
- **React API:** a local FastAPI adapter now supports scientific investigation endpoints and the isolated Planetary Computer STAC endpoints. Investigation history is in-memory only; job queues, cancellation, durable history, and real-time processing status do not exist. Keep the service bound to localhost until upload isolation, quotas, cleanup, and authentication are addressed.
- **Periodicity:** the Lomb-Scargle result is a screening candidate, not an explanation. The automatic cadence/baseline period bounds are heuristics; aliases, red noise, and detector/systematic effects are not modeled, the per-source analytic false-alarm estimate is not multiplicity-corrected or a substitute for end-to-end calibration, and no real SPHEREx light curve validates this analysis.
- **Cross-modal inference:** image, temporal, spectral, motion, and hypothesis results are preserved together with their evidence and compatibility decisions, but no joint probabilistic or causal model combines them. Outputs remain separate findings; a shared report is not evidence fusion.
- **Multi-epoch source association:** track IDs are heuristic labels, not source identities. Ambiguous or low-confidence matches remain separate. Temporal variability remains untestable for the synthetic dataset because no validated response evidence is supplied; the FITS source extractor also does not generate sensitivity-backed non-detections, so it cannot make transient-candidate claims from absence alone.
- **Persistence:** classifier requires explicit compatible sensitive detections and non-detections across at least three epochs. FITS source extraction currently records detections only; it cannot claim sensitivity on missing epochs.
- **Hypotheses:** computed moving-object and artifact cards are conservative. Independent reference catalogues, proper-motion/parallax prediction, detector-pattern classifiers, neighbor/PSF modeling, and persistence tests are not connected. Cards remain UNTESTABLE where those inputs are absent.
- **Astrometry:** source matching is nearest-neighbor with pixel-scale and measured-error bounds, not proper-motion-aware. The centroid uncertainty is an independent-pixel approximation and omits WCS, pointing, and distortion systematics.
- **Quality flags:** the existing Level 2 reject-bit policy was exercised on one current product but its bit semantics and consequences still require independent validation across representative products.
- **Archive resilience:** query and download outcomes are distinguished, timeouts are finite, and successful requests are cached. Automatic retries and paginated result traversal are not implemented.
- **App end-to-end:** local startup, synthetic demo, and FITS upload were browser-smoke-tested. No live IRSA request or real-data scientific validation was performed for Mission Control.
